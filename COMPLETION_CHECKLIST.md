# Watchdog completion ledger

Owner: current Codex/Astra conversation. Base: 07d35f5. Implementation: interactive Devin, exact `--model swe-2`, no fallback. Understood as: atomize the remaining product work, launch at most two isolated workers, independently verify candidates, and progress until product evidence or a concrete authority boundary.

## Contracts

Each row is one assignment, one primary artifact, one principal oracle. Workers have at most two Todo items, no subagents, no commit/push/merge/tag/publish/deploy or worktree deletion. Allowed source paths are row-specific; build outputs belong inside that task worktree. Reports are terminal responses. Owner reviews scope, diff and oracle before accepting. A blocked task receives at most one narrowed retry on SWE-2. Preserve rejected diffs and evidence; rollback means omit the candidate from owner integration, never reset user files.

Evidence: L=source/build, S=synthetic test, R=real runtime, D=downloaded/installed distribution, H=human observation. Gates: none=local scope; QA=disposable runtime and OS permission interaction; ACCOUNT=external configuration; PUBLISH=explicit commit/push/merge/release permission; APPLE=optional paid distribution policy and credentials.

Existing baseline (not new work): identity authorization, stale gating, metrics, monotonic thresholds, bounded helpers, normalization and 79 passing unit tests from prior audit. They remain regression checks. Prior UI success was historical CI, not current local execution. No-paid unnotarized beta is the existing policy; notarization is NOT a mandatory blocker. Sandbox absence alone is not a defect for this process-control utility. Existing installer uses rename/backup but full crash-atomic recovery is unproven. Proposed soak limits are acceptance targets, not past measurements.

## DAG and execution waves

First wave: A01 and A03, each isolated from 07d35f5. Owner accepts each diff and reruns its focused oracle before integration. Wave 2: A02 and A04 on accepted owner contents. Then A05/A07; A06/A08; A09/A10; conditional A11/A12; A13 plus A20; A14 plus A21; A15-A18 sequential plus A22; A19/A23; A24-A26; A27-A29. B tasks may run alongside only where predecessors and file ownership allow. All runtime claims bind to the integrated candidate, never a worker's omitted snapshot. B12 joins all gates; B13 requires publication authority. C tasks do not block the existing no-paid beta objective.
