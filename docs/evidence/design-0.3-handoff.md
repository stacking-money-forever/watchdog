# Watchdog 0.3 디자인 핸드오프 (D1)

작성 2026-10-30. 사용자가 IA 승인 게이트를 생략했으므로(2026-10-30) 이 문서가 구현 기준이다. 변경은 이 문서를 먼저 고친다.

## 1. 독자와 과업

- **독자**: 한 Mac에서 코딩 에이전트를 여러 개 띄워 두는 개발자. 터미널 10개 이상, 에이전트 세션 10개 이상이 보통이다(2026-10-30 실기: claude 12, codex 서비스 3, opencode 서비스 1).
- **주 과업** (빈도순):
  1. "지금 뭔가 무거운가?" — 메뉴바 아이콘만 보고 안다. 열지 않는다.
  2. "어느 세션이 무겁나, 멈춰도 되나?" — 팝오버에서 세션 단위로 보고 한 번에 멈춘다.
  3. "Watchdog이 뭘 했나, 되돌릴까?" — 팝오버의 최근 조치 또는 창의 조치 기록.
  4. "남아 있는 찌꺼기 정리" — 고아 프로세스 목록에서 종료.
  5. 규칙 조정(가끔), 전체 프로세스 검색(드묾).
- **진입점**: 메뉴바 아이콘 클릭(팝오버), 팝오버의 "창 열기", 시스템 알림 클릭(창의 해당 세션으로), `watchdog-cli`(창을 열지 않음).
- **관찰 가능한 성공**: 팝오버를 연 뒤 두 번 이내의 클릭으로 세션을 멈추고, 메뉴바 아이콘이 "조치함" 상태로 바뀌며, 조치 기록에 사유(CPU %·지속 초)가 남는다.

## 2. 정보 계층

### 메뉴바 아이콘 (항상 보임)
| 상태 | 모양 | 의미 |
|---|---|---|
| 정상 | 개 실루엣(템플릿 이미지) | 주의 항목 0, Watchdog이 멈춘 프로세스 0 |
| 주의 | 실루엣 + 우상단 점(주황) | 지속 CPU/메모리 초과 또는 고아 ≥1 |
| 조치함 | 실루엣 + 우상단 일시정지 기호(파랑) | Watchdog이 멈춘 프로세스 ≥1 (주의보다 우선) |
| 오래됨 | 실루엣 흐림(secondary) + 느낌표 | 샘플링 실패/지연 → 제어 비활성 |

색만으로 구분하지 않는다(점/일시정지/느낌표). 접근성 레이블: "Watchdog, 주의 2건" 같은 문장.

### 팝오버 (380×520, 기존 크기 유지)
```
┌────────────────────────────────────────────┐
│ Watchdog            CPU 31%  MEM 62%   [창] │  header: 시스템 요약 + 창 열기
├────────────────────────────────────────────┤
│ ⚠ 주의 2 · ⏸ 멈춤 1                 [⟳]  │  상태 줄 (없으면 "문제 없음 · 세션 12개")
├────────────────────────────────────────────┤
│ 세션                                        │
│ ▸ claude · watchdog     184% · 1.9GB  [⏸]  │  세션 행: 이름·프로젝트·합계·1차 조치
│     CPU 높음 2분 · 자식 4                   │  보조 줄: 사유 + 멤버 수
│ ▸ codex · dev (서비스)   2% · 0.3GB   [⏸]  │
│ ▸ claude · brgr          3% · 0.6GB   [⏸]  │
│   … (주의 항목 먼저, 그다음 CPU순, 최대 8)   │
│ 고아 1                                      │
│   codex app-server (임시 경로) 3일   [종료] │
├────────────────────────────────────────────┤
│ 최근 조치                                   │
│ ⏸ claude · watchdog 자동 정지 · 12초 전 [되돌리기] │
├────────────────────────────────────────────┤
│ 창 열기 ⌘O · 설정 · 종료                     │
└────────────────────────────────────────────┘
```
- **1차 조치**는 세션 행마다 하나(멈춤 또는 재개). 종료·강제 종료·무시는 행의 `…` 메뉴로 내려 보낸다(현재와 같이 확인 카드).
- 세션 행을 펼치면(▸) 멤버 목록(최대 6, 나머지는 "창에서 보기").
- 팝오버에는 **검색·규칙 슬라이더를 두지 않는다**. 창으로 옮긴다.
- 빈 상태: "문제 없음 · 세션 N개 감시 중". 세션 0: "실행 중인 코딩 에이전트가 없습니다".
- 오래됨: 상태 줄이 "관찰 정보가 오래되어 제어할 수 없습니다 · 새로고침"으로 바뀌고 모든 조치 버튼 비활성(기존 계약).

### 창 (기본 820×560, 최소 680×420) — `NavigationSplitView`
| 사이드바 | 내용 | 1차 조치 |
|---|---|---|
| 개요 | 아이콘 상태 설명, 시스템 CPU/MEM, 주의/멈춤/고아 수, 최근 조치 5건, 감지 규칙 요약 | 창 안 이동 |
| 에이전트 세션 | 세션 테이블(이름·프로젝트·CPU 합·MEM 합·자식 수·상태·시작), 행 펼치면 멤버 트리(들여쓰기, 각 멤버 CPU/MEM) | 세션 멈춤/재개, 멤버 개별 조치는 `…` |
| 전체 프로세스 | 현재 "전체" 범위 목록 + 검색(⌘F) + 필터(에이전트/서비스/앱/시스템/고아) + 정렬 | 기존 행 조치 |
| 조치 기록 | 저널 테이블(시각·출처 app/auto/cli·조치·대상·사유·결과), 되돌리기 가능한 행에 버튼, 내보내기(JSON) | 되돌리기 |
| 감지 규칙 | CPU 임계값, 메모리 임계값, 유지 시간, 자동 정지(끔/에이전트만/세션 전체), 사용자 규칙 파일(이름·패키지·서비스·호스트 편집, 유효성 표시) | 저장 즉시 반영 |
| 설정 | 알림, 로그인 시 실행, CLI 링크 안내, 진단(doctor 결과), 정보 | — |

## 4. 상호작용·접근성

- 키보드: 팝오버/창 목록 ↑↓ 이동, Return 펼침, Space 1차 조치, ⌘F 검색(창), ⌘Z 마지막 조치 되돌리기(가능할 때만), Esc 확인 카드 취소, ⌘O 창 열기, ⌘, 규칙.
- 포커스: 확인 카드가 열리면 "취소"에 포커스, 닫히면 원래 행으로 복귀. 되돌리기 후 포커스는 기록 행 유지.
- 접근성 이름: 세션 행 = "claude, watchdog 프로젝트, CPU 184퍼센트, 메모리 1.9기가바이트, 주의: CPU 높음 2분, 자식 4개". 버튼 = "세션 일시 정지", "세션 재개", "되돌리기".
- 안내문(`AccessibilityNotification.Announcement`): 조치 결과("claude 세션을 멈췄습니다"), 자동 조치 발생.
- 식별자 규칙: `watchdog.<영역>.<요소>` 및 `session.<rootPID>.<startµs>.<요소>`, `process.<pid>.<startµs>.<요소>`(기존 유지), `journal.<entryID>.<요소>`.
- 모션: 펼침/배지만 기본 애니메이션, `accessibilityReduceMotion`이면 없음.
- 문구: 한국어, 기존 톤(평서문, "~합니다"). 영문 이름(에이전트·프로젝트)은 그대로.

## 5. 재사용과 신규 컴포넌트

- 재사용: `ProcessRow`(멤버 행·전체 프로세스 행), 확인 카드, 피드백 배너, `WatchdogMenuBarLabel`.
- 신규: `SessionRow`(팝오버·창 공용), `StatusLine`, `JournalRow`, `RulesEditor`, `SidebarItem` enum, `MenuBarIcon`(상태별 심볼 합성).
- 삭제: 팝오버의 범위 세그먼트(주의/에이전트/전체), 팝오버 내 `DisclosureGroup("감지 규칙")`, 팝오버 검색창.

## 6. 의도적 생략

- 그래프/스파크라인: 숫자와 지속 시간으로 충분. 그리기 비용과 메모리(0.2.x에서 메뉴바 그래프 메모리 문제) 때문에 넣지 않는다.
- 세션별 프로세스 트리 전체 펼침 기본값: 기본 접힘. 자식 수와 합계만.
- 테마/색 커스터마이즈: 없음. 시스템 외형만 따른다.

## 7. 구현 순서와 본보기

U1 창 골격 → **U2 팝오버(본보기)** → Fable 검토(스크린샷·접근성 트리·CLI 대조) → U3~U6. 본보기 검토에서 이 문서와 어긋나면 문서를 고치고 다음 단위에 반영한다.
